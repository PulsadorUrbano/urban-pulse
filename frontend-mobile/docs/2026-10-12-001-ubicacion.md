# Sesión — 2026-10-12 · Feature 001 · Ampliación: módulo de ubicación

## Contexto

La feature 001 (registro de incidencia) está en "Hecho " con título, descripción, categoría
opcional y rediseño de UI. En esta sesión se **planifica** una nueva ampliación de esa misma
feature: capturar la **ubicación** del ciudadano al registrar una incidencia. Igual que en la
ampliación de categoría, aquí **solo se actualiza la documentación de `spec/`**; **no** se toca
`src/` ni `db.json` y **no** se crea una feature nueva.

## Alcance de la ampliación

- Nueva entidad `Location { id: string; latitude: number; longitude: number; accuracy: number | null; createdAt: string }`
  con relación 1:M con `Incident` vía `locationId`; colección `locations` en el mock.
- `CreateIncidentInput` añade `locationId?: string | null` (`Incident` ya declara `locationId`).
- **Toggle de ubicación** flotante en la esquina inferior derecha: círculo grisáceo + icono blanco
  Material `location_on` con **línea diagonal** cuando está desactivado; **activado por defecto**.
- Captura al pulsar Enviar con el toggle activado: posición con `Accuracy.Balanced` → se crea la
  `Location` y la incidencia se guarda con `locationId`.
- Permiso: **siempre se intenta pedir** si no está concedido; si no puede concederse, `Alert` con
  **"Abrir Ajustes"** (`Linking.openSettings()`), **"Enviar sin ubicación"** y **"Cancelar"**.
- GPS apagado o fallo de captura → envío con `locationId: null` y aviso no bloqueante.
- **Advertencias combinadas**: `getIncidentWarnings({ description, isLocationEnabled })` con
  `description-empty`, `description-too-short` y `location-disabled`; un único `Alert` antes de
  enviar.

## Decisiones clave

- `Location` separada de `Incident` (1:M vía `locationId`) para reutilizarla en features futuras;
  alternativa descartada: incrustar lat/lng en `Incident`.
- `Accuracy.Balanced` para equilibrar precisión, batería y tiempo de respuesta; la precisión real
  se guarda en `Location.accuracy` (contempla `null` en web).
- Captura **al enviar**, no al montar el formulario: sin permisos ni GPS hasta que el ciudadano
  confirma.
- Un único `Alert` combinando avisos: los avisos nunca bloquean, solo piden confirmación.
- `Linking.openSettings()` (nativo, iOS + Android) cuando el permiso no puede volver a solicitarse;
  el registro nunca se bloquea ("Enviar sin ubicación" / "Cancelar").
- `device-location.ts` (hardware/permisos) separado de `location.service.ts` (mock REST
  `POST /locations`) para poder mockear `expo-location` en tests.
